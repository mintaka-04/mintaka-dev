## 배운 것

### Docker 네트워크 구조

#### 컨테이너는 자기만의 IP를 가진다

컨테이너는 독립된 네트워크 네임스페이스를 가진다. 예를 들어 컨테이너 IP가 `172.17.0.2`라면, 호스트의 `127.0.0.1`과 컨테이너의 `127.0.0.1`은 완전히 다른 주소다.

#### 브라우저 → Flask 접근 흐름

```
브라우저 → localhost:5000
        ↓
① 호스트 5000 포트로 들어옴
        ↓
② 포트포워딩 (docker-compose.yml의 5000:5000)
   호스트 5000 → 컨테이너 5000 으로 전달
        ↓
③ Flask가 IP 판단
   127.0.0.1 설정 → 172.17.0.2 거부 ❌
   0.0.0.0 설정   → 모든 IP 허용 ✅
```

포트 바인딩이 먼저, Flask의 IP 판단은 그 이후다.

#### `0.0.0.0`의 의미

Flask를 `0.0.0.0`으로 바인딩하면 "어떤 IP로 오든 다 받겠다"는 의미다.

- `0.0.0.0` 없으면 → 컨테이너 IP(`172.17.0.2`)로 들어오는 트래픽 거부 → 브라우저 접속 불가
- `0.0.0.0` 있으면 → 컨테이너 IP로 와도 수신 → 브라우저 접속 가능

#### `172.17.0.2:5000`을 브라우저에 직접 입력하면?

호스트의 포트포워딩을 거치지 않고 인터넷에서 `172.17.0.2`를 찾으러 간다. Docker 내부 IP라 인터넷에 존재하지 않으므로 접속 불가.

#### docker-compose.yml 포트 표기

```yaml
ports:
  - "5000:5000"
  #   ↑       ↑
  # 호스트  컨테이너
  # 포트    포트
  #           ↑
  #           app.py의 port=5000 과 일치해야 함
```

#### 전체 보안 구조

컨테이너가 `0.0.0.0`으로 열려 있어도, Docker 내부 네트워크에 있기 때문에 호스트 포트포워딩을 통해서만 외부 접근이 가능하다.

- 외부 보안 = 호스트(방화벽/보안그룹)가 담당
- 내부 판단 = Flask(`0.0.0.0`)가 담당
